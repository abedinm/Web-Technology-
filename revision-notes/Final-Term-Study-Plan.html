Seven days to the term exam. Built from the official course outline: what is actually examinable, what it is worth, and what to do on each of the seven days.

Read this first

The term exam is the whole game. It is 60% of the final term, and the final term is 60% of the course — so this one paper decides 36% of your entire course grade. Nothing else you can still influence comes close.

The final term outweighs the midterm. The course is 40% midterm and 60% final term. A poor midterm does not decide your grade; this term does more of the deciding than the one you already sat.

Four topics are new to you. Your revision sheet covers PHP basics, forms, sessions, cookies, AJAX and JSON. It does not cover PHP & MySQL, MVC, web security, or API fundamentals — and all four are on the final. They are Days 1 to 3 below.

4Day 1 material — PHP & MySQL

Week 11. The largest new topic and the most likely long-form code question.

Connect, then always check

<?php
$conn = mysqli_connect("localhost", "root", "", "school_db");

if (!$conn) {
    die("Connection failed: " . mysqli_connect_error());
}
?>

SELECT and display — the most common question

$result = mysqli_query($conn, "SELECT id, name, email FROM students");

while ($row = mysqli_fetch_assoc($result)) {
    echo $row["name"] . " - " . $row["email"] . "<br>";
}

echo mysqli_num_rows($result);      // how many rows came back

INSERT, UPDATE, DELETE

mysqli_query($conn, "INSERT INTO students (name, email)
                     VALUES ('Minhaz', 'm@mail.com')");

mysqli_query($conn, "UPDATE students SET name = 'Rahim' WHERE id = 1");

mysqli_query($conn, "DELETE FROM students WHERE id = 1");

mysqli_close($conn);

Prepared statements — the safe way, and worth double marks

$stmt = mysqli_prepare($conn, "INSERT INTO students (name, email) VALUES (?, ?)");

mysqli_stmt_bind_param($stmt, "ss", $name, $email);   // "ss" = two strings
mysqli_stmt_execute($stmt);

// Reading results back from a prepared statement
$stmt = mysqli_prepare($conn, "SELECT * FROM students WHERE email = ?");
mysqli_stmt_bind_param($stmt, "s", $email);
mysqli_stmt_execute($stmt);
$result = mysqli_stmt_get_result($stmt);
$row    = mysqli_fetch_assoc($result);
The bind_param type letters: s string  ·  i integer  ·  d double  ·  b blob. One letter per ?, in order. Two placeholders and one letter is an error.

Why it earns marks twice: a prepared statement sends the SQL and the data separately, so user input can never be read as SQL. That is the textbook answer to “how do you prevent SQL injection” as well as a MySQL question.

5Day 2 material — Web Security

Week 13. Mostly written answers, which makes it cheap marks for the time spent.

AttackWhat it isThe fix
SQL InjectionUser input is treated as SQL, e.g. typing ' OR '1'='1 into a login boxPrepared statements with bind_param
XSS
(Cross-Site Scripting)		User input containing <script> is echoed back and runs in another user's browserhtmlspecialchars() on all output
CSRF
(Cross-Site Request Forgery)		A user who is logged in is tricked into submitting a request they did not intendA random token in every form, checked on submit
Session hijackingAn attacker steals or fixes the session ID and becomes that usersession_regenerate_id(true) on login; HttpOnly cookies; HTTPS
Weak password storagePasswords kept as plain text or MD5, readable if the database leakspassword_hash() and password_verify()

Password handling — near-certain question

// Registering
$hash = password_hash($password, PASSWORD_DEFAULT);

// Logging in
if (password_verify($input, $user["password"])) {
    session_regenerate_id(true);      // stops session fixation
    $_SESSION["user_id"] = $user["id"];
}
Say this if asked why hashing: hashing is one-way. You can never turn a hash back into the password — you can only hash the attempt and compare. So even if the database leaks, the passwords are not exposed. Never use MD5 or SHA1 for passwords; they are too fast to compute and are considered broken for this purpose.

6Day 3 material — MVC

Week 11. Theory only — DoctorConnect is procedural, so there is no example of this in your own work.

LayerResponsibilityIn a PHP app
ModelThe data and the rules around it. Talks to the database. Knows nothing about how it is displayed.A class or file holding the SQL queries
ViewWhat the user sees. Displays data it is handed. Contains no business logic.The HTML template
ControllerReceives the request, asks the Model for data, chooses which View to show.The script the form posts to

Why MVC is used: separation of concerns, so a change to the layout cannot break the database code; easier testing, because the Model can be tested without a browser; and easier teamwork, since one person can work on views while another works on data.

If asked to compare: in a procedural PHP page the SQL, the logic and the HTML all sit in one file — quick to write, hard to maintain. MVC splits them into three, which costs more setup but scales to larger applications and larger teams.

7Day 3 material — API fundamentals

Week 13. Small topic, mostly definitions and two lists.

API = Application Programming Interface. A defined way for one program to request data or actions from another, without knowing how it works inside. REST is a style of API where each resource has its own URL and you act on it with standard HTTP methods.

MethodDoesExample
GETRead dataGET /students — list all students
POSTCreate something newPOST /students — add a student
PUTUpdate an existing itemPUT /students/5
DELETERemove an itemDELETE /students/5

Status codes worth memorising

CodeMeaningCodeMeaning
200OK — request succeeded401Unauthorized — not logged in
201Created404Not Found
400Bad Request500Internal Server Error

APIs almost always exchange JSON, which is why AJAX, JSON and APIs are taught together — json_encode() on the server, fetch() and res.json() on the client.
